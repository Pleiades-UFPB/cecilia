<objective>
## Goal
Qualquer aluno, a partir de um clone limpo, roda `uv sync && uv run pytest` sem erros, com versões de dependências fixadas em `uv.lock`; o mesmo é verificado automaticamente a cada PR pelo GitHub Actions.

## Purpose
Reprodutibilidade é o valor central do projeto (AC-T.1). Sem ambiente travado, cada aluno teria versões diferentes de pandas/astropy/xgboost e resultados numéricos diferentes. O CI faz o revisor da fase ver "checks verdes" antes de aprovar o PR, casando com a proteção da `main`.

## Output
- `.python-version` (3.11 — versão mínima suportada)
- `pyproject.toml` com configuração de pytest e regras do ruff
- `uv.lock` versionado
- `tests/test_fumaca.py`
- `.github/workflows/ci.yml`
- Seção "Ambiente" do README atualizada
</objective>

<acceptance_criteria>

## AC-1: Ambiente sobe do zero (AC-01.1)
```gherkin
Given um clone limpo do repositório, sem .venv
When `uv sync && uv run pytest` é executado
Then o ambiente é criado com Python 3.11 e as versões exatas do uv.lock, e o pytest termina com todos os testes passando
```

## AC-2: Teste de fumaça detecta ambiente quebrado
```gherkin
Given o ambiente instalado
When `uv run pytest tests/test_fumaca.py -v` roda
Then verifica que o pacote `cecilia` importa, que `cecilia.__version__` é igual à versão do pyproject.toml e que as dependências científicas principais (numpy, pandas, pyarrow, astropy, astroquery, sklearn, xgboost, imblearn, shap, matplotlib, plotly) importam
And se qualquer import falhar, o teste falha com mensagem indicando qual biblioteca
```

## AC-3: Lint e formatação padronizados
```gherkin
Given o código em src/ e tests/
When `uv run ruff check .` e `uv run ruff format --check .` são executados
Then ambos terminam sem erros
```

## AC-4: CI verifica cada PR
```gherkin
Given um PR aberto contra a main (ou push na main)
When o workflow de CI roda no GitHub Actions
Then executa `uv sync --locked`, `ruff check`, `ruff format --check` e `pytest`, e falha se o uv.lock estiver desatualizado em relação ao pyproject.toml
```

<task type="auto">
  <name>Task 1: Fixar Python e dependências, configurar pytest e ruff</name>
  <files>.python-version, pyproject.toml, uv.lock</files>
  <action>
    - Criar `.python-version` com `3.11`. Motivo: é o mínimo declarado em `requires-python`; desenvolver na versão mínima evita usar sintaxe que quebraria em 3.11.
    - Em `pyproject.toml`:
      - `[tool.pytest.ini_options]`: `testpaths = ["tests"]`, `addopts = "-ra"`.
      - `[tool.ruff]`: manter `line-length = 100`, adicionar `target-version = "py311"`.
      - `[tool.ruff.lint]`: `select = ["E", "F", "I", "UP", "B"]` (erros de estilo, pyflakes, ordenação de imports, modernização, bugs comuns). Não ativar regras de docstring (D) — muito ruído para quem está aprendendo; docstrings em português são exigidas pelo CLAUDE.md, não pelo linter.
    - NÃO adicionar nem remover dependências de runtime. Não fixar versões no pyproject (quem fixa é o uv.lock).
    - Rodar `uv lock` e `uv sync` para gerar `uv.lock` e `.venv`.
    - Evitar: commitar `.venv/` (já está no .gitignore).
  </action>
  <verify>`uv sync` termina sem erro; `uv run python --version` mostra 3.11.x; `uv.lock` existe; `uv lock --check` passa</verify>
  <done>AC-1 parcialmente satisfeito: ambiente reprodutível travado em uv.lock com Python 3.11</done>
</task>

<task type="auto">
  <name>Task 2: Teste de fumaça e conformidade com ruff</name>
  <files>tests/test_fumaca.py</files>
  <action>

O id de cada caso é o nome do módulo, para a falha dizer qual biblioteca quebrou.

    - Evitar: testes que acessem rede (astroquery só é importado, nunca consulta).
  </action>
  <verify>`uv run pytest -v` mostra 12 testes passando (1 + 11 parametrizados); `uv run ruff check .` e `uv run ruff format --check .` sem erros</verify>
